# Sprint 02 日志格式与解析规则

## 数据来源与保证范围

仓库没有真实用户日志。`sample.log` 是保留的第一阶段关键字演示，`legacy-synthetic.log` 与 `waylith-synthetic.log` 是本阶段人工构造的结构样本；它们都不是真实 RimWorld 日志，也不代表覆盖所有版本。

2026-10-30 编码前对少量公开原始日志的结构做了只读观察：

- [HugsLib 公开的 1.7 日志](https://gist.github.com/HugsLibRecordKeeper/ca654f7e2b4792e2fafa2465d29b2886)：可观察到日期时间、等级、方括号来源组成的记录头，以及其后独立的 `at` 堆栈行。仅用于确认这一前缀与续行特征，没有将玩家日志复制进仓库。
- [Multiplayer 用户问题报告中的旧版原始日志](https://github.com/rwmt/Multiplayer/issues/217)：可观察到无时间戳消息、Unity 堆栈和 Verse 的 Message/Warning/Error 调用。此报告的游戏版本为 1.3，因此是 Legacy 历史风格的证据，不是对全部 1.6 日志的实测验证。

没有依赖第三方诊断结论，也没有据此建立 Mod 根因规则。格式名称是语法分类，不是可靠的版本鉴定。

## 支持的记录头

### Waylith

合成语法示例：

```text
2026-10-30 12:00:01.002 ERROR [Verse] SyntheticException: 合成消息
at Synthetic.Mod.Tick() in Synthetic.dll:token 0x6000001+0x0
2026-10-30 12:00:02.003 INFO [Verse] Exception handler initialized
at Synthetic.Info.Initialize()
```

必须从行首开始。时间戳语法为 `YYYY-MM-DD`，以空格或 `T` 连接 `hh:mm:ss`，可选小数秒（`.` 或 `,`）及 `Z` / `±hh:mm`。这是语法匹配，不验证日期的日历有效性。接受的等级为大写 TRACE、DEBUG、INFO、WARN、WARNING、ERROR、EXCEPTION、FATAL；来源须为非空 `[来源]`。消息可以为空。ISO 变体属于本工具容许的输入扩展，不声称每种变体均已在真实游戏中观察到。

记录头中的等级是权威字段：INFO 正文、来源或堆栈出现 Error / Exception 字样，也不改变等级。WARN / WARNING 统一为 WARNING，EXCEPTION 统一为 ERROR。时间戳保留原字符串，不擅自转换时区。

### Legacy

接受行首 `[等级] 消息`、`等级: 消息`（等级忽略大小写），以及部分常见标题：以 `Error `、`Warning `、`Exception ` 开始的文本、`Root level exception` 和以标准 ASCII 类型名称组成的 `...Exception:`。这些明确前缀同样适用于合成演示，不代表旧游戏总会打印等级前缀。

旧日志中任意消息后可能直接跟随 Unity 堆栈。对于未提供明确等级的记录，使用第一个已识别的 `Verse.Log:Message/Warning/Error/ErrorOnce` 或对应 `_Patch数字` 调用帧提供等级证据。任意其他类的 `Log.Error` 或带有 Error 的方法名，不提供这个证据。明确的等级前缀始终优先；无前缀的启发式异常标题可由 Verse 的 Message 调用修正为 INFO。

## 事件边界

1. **先判断堆栈，再识别记录头。** 识别去除缩进后的 `at `、`(wrapper `、`--- End of `，以及 `类型:方法(...)` 风格的 Unity 帧。堆栈中的 Error 不开始新事件。
2. 明确的新记录头结束上一事件，包括 ERROR 后的 INFO。新记录拥有其后堆栈，不向前合并。
3. 已有堆栈后出现非空、非堆栈、非已识别元数据的无标记正文时，结束上一记录，创建新记录。它的后续堆栈只归入新记录；如果出现明确的 Verse 调用，可再确定其等级。
4. 无法识别的文本创建 Unknown 记录。未标记的正文续行暂保留在当前事件内并设置 `boundary_uncertain`，因为无法断言它是消息续行还是下一条未标记消息。
5. 空行、`[Ref ...]` 和 `(Filename:...)` 元数据保留在原文中；堆栈后的空白分隔符与这些元数据不作为消息正文参与去重。未知元数据不随意剥离。
6. EOF 结束当前事件，即使堆栈截断；不编造缺失帧，也不能可靠区分合法短堆栈与意外截断。

所有行都归入某个事件，行号从 1 开始，起止位置为包含端点的范围。原文保留实际 LF/CRLF 和首行 BOM；解析字段去除行末换行，消息多行以 LF 连接。尾部空行或已识别元数据可能属于前一事件，因而其 EndLine 包含这些行。

Unknown 不被直接当成诊断。即使其中出现 Error 或 Exception，也仅保留原文供人工复核。完全未知或空文件的格式为 Unknown；混合已识别格式的文件汇总为 Unknown，各事件仍保留独立格式。

## 去重算法

只处理 ERROR、WARNING、FATAL 事件；INFO、DEBUG、TRACE、UNKNOWN 不参与。

逐条构造比较键：`(Level, Source, Message, 逐帧修剪两端空白后按 LF 连接的 Stack)`，用 map 定位诊断组，按首次出现的顺序输出。记录头的时间戳、原始文本和行号不进入比较；Source 作为来源区分保留，避免跨来源错误合并。

不删除正文数字、路径、Mod 标识、堆栈方法名、代码位置、偏移或 token；这些任意不同都会保留不同组。无堆栈和有堆栈也不同组。两条消息相同且堆栈均为空时会合并，但不声称它们具有相同根因。

每组保留第一条完整事件、发生次数、首次与末次出现各自的起止行号。`events` 另保留每次出现的完整原文，不因合并而删除记录。这里比较的是结构内容相同，不是根因相同。

## 尚未支持或无法可靠判断

- 任意 Mod 自定义包装、带线程/颜色/其他前缀的记录头、未知或小写 Waylith 等级：可能落入 Unknown 或带不确定标记的上下文。
- 无明确头、无间隔、无堆栈的相邻普通消息：无法总是拆开；多行正文和下一条无标记正文也可能有歧义。
- 无缩进且看起来像新异常标题的内部异常：可能被拆成新事件；复杂异步/嵌套堆栈没有专门建模。
- `[Ref ...] Duplicate stacktrace` 等引用不会展开，缺失堆栈不会根据引用猜补，因此可能无法与原完整堆栈合并。
- 缺少可识别等级的旧版日志、原生引擎崩溃、混杂系统诊断、特殊堆栈标记：保留原文，但不保证正确分类或完整提取语义字段。
- 不进行游戏版本验证、编码自动转码、增量监控或读取期间的一致性保证。JSON 针对有效 UTF-8 文本；Go JSON 编码器会替换无效 UTF-8 字节，所以不是任意二进制输入的无损导出。
- 解析结果保留全部原文和正文，内存随输入规模增长；尚未提供分页、磁盘索引或资源上限。
